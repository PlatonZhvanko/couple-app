# Архитектура

## Папки

```
CoupleApp/
  App/                 запуск приложения и нижняя панель вкладок
  Core/                общее для всех разделов
    Features/          описание раздела (Feature) и список вкладок (FeatureRegistry)
    Persistence/       локальная база SwiftData (AppDatabase)
    Sync/              синхронизация между телефонами (Supabase)
    DesignSystem/      общие элементы интерфейса
  Features/            разделы приложения, каждый в своей папке
    Planner/           Планер / календарь
    Nutrition/         Питание
    Sleep/             Сон
    Mood/              Настроение
    Clients/           Клиенты
    Car/               Авто
    Settings/          Настройки
  Resources/           иконка, цвета
docs/                  инструкции и SQL для Supabase
```

Проект использует «синхронизированные папки» Xcode 16: любой файл, положенный
в папку `CoupleApp/`, автоматически попадает в приложение. Файл проекта
(`project.pbxproj`) при этом не меняется, поэтому разделы можно разрабатывать
параллельно без конфликтов.

## Раздел

Каждый раздел — это папка `Features/<Раздел>/` и одно значение `Feature`
в файле `<Раздел>Feature.swift`: id, название, иконка, модели данных и корневой экран.
Список вкладок задаётся в `Core/Features/FeatureRegistry.swift`.

Правила для разделов:

- Код раздела лежит только в его папке. Общие вещи — в `Core/`.
- Разделы не обращаются к типам других разделов напрямую.
- Имена типов начинаются с названия раздела (`NutritionMeal`, `CarRefuel`),
  чтобы не было совпадений.

## Данные

- Всё хранится локально в SwiftData (`Core/Persistence/AppDatabase.swift`).
  Модели раздела перечисляются в `models` его `Feature`.
- Если данные должны быть видны на втором телефоне, модель реализует
  `SyncableModel` (см. `Core/Sync/SyncableModel.swift` и пример
  `Core/Sync/Example/ExampleNote.swift`).
- Требования к моделям SwiftData: `@Model final class`, у всех свойств есть
  значения по умолчанию (так проще менять модели без миграций).

## Синхронизация

```
SwiftData (телефон A)  ⇄  SyncCoordinator  ⇄  Supabase: таблица records  ⇄  телефон B
```

- Сначала локально, потом на сервер: приложение работает офлайн.
- Все типы данных лежат на сервере в одной таблице `records`
  (`kind` + JSON `payload`), поэтому новому разделу не нужны изменения на сервере.
- Конфликты: побеждает более позднее изменение (`updatedAt`).
- Удаление — мягкое (`deletedAt`), чтобы оно дошло до второго телефона.
- Синхронизация запускается при открытии приложения, раз в минуту, по «потянуть
  вниз» и после изменений (`sync.requestSync()`).
- Код сервера изолирован в `Core/Sync/Supabase/`. Чтобы сменить сервер, достаточно
  новой реализации протокола `SyncBackend`.
